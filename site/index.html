What the two numbers say

What the diver is actually doing

An agent with a goal and no map has only one honest option: explore systematically. Depth-first search is the most committed version of that idea. Faced with several passages, it picks one and follows it to the end before considering any other.

Chambers are states. Passages are actions. The rope is the stack. The markers are the visited set. Nothing in the game is decoration: each piece is a part of the algorithm wearing a costume.

Three ingredients

The state space

Every chamber the diver could stand in, and every passage out of it.

The visited set

What has already been fully searched. Without it the search never ends.

The stack

Unfinished decisions, newest first. The rope behind the diver.

The algorithm

visit the starting chamber, mark it, push it
repeat:
    current ← top of stack
    if current has a neighbour that is not marked:
        visit it, mark it, push it          ← go deeper
    else:
        pop current                          ← follow the rope back
until the stack is empty

The stack holds only the path the diver is standing on, not every chamber he has discovered. That single detail is the reason the memory cost is O(m) rather than O(b×m), and it is what separates DFS from BFS more than the order of exploration does.

What it costs

Let b be the average number of passages out of a chamber and m the greatest depth. Move the sliders and watch the two numbers pull apart.

Chambers it may enter — time O(bm) 1.1 trillion
Chambers it must remember — space O(m) 20

Is it any good?

Complete? No Down an infinitely long passage it commits forever and never returns. Try the endless passage in the Playground.
Optimal? No With one charging station three moves away and another twenty, DFS can reach the twenty-move one first and stop there.
Time O(bm) In the worst case it enters nearly every chamber. DFS changes the order of exploration; it does not reduce how many states exist.
Space O(m) Only the current path. This is where DFS wins, and it wins big.

Choosing between them

Reach for DFS when

  • memory is the scarce resource
  • the search space is enormous
  • you must explore a huge design space
  • any solution will do

Reach for BFS when

  • you need the shortest solution
  • you need the nearest exit
  • the goal is likely to be close by
  • branches may be infinite

These are not competing answers to one question. They are different policies for choosing which state to look at next. DFS says stack. BFS says queue. Uniform cost search says priority queue ordered by path cost. A* says priority queue ordered by cost plus heuristic. Same skeleton, different rule.

Where this pattern shows up

  • Backtracking puzzles — Sudoku solvers and N-Queens guess, check, and undo.
  • Directory trees — walking a filesystem goes depth-first almost by instinct.
  • Recursive parsing — reading nested JSON or XML descends and returns.
  • Constraint problems — scheduling, timetabling and SAT solving all guess, detect a conflict, and backtrack.
  • Game engines — chess searches depth-first, but with pruning, because exploring every branch is impossible.
  • Program synthesis — write a program, test it, fail, modify, try again.

It also describes something closer to home. A language model working through a chain of reasoning usually follows one line of argument at a time rather than every possible argument at once, and some inference methods deliberately branch and abandon a weak line. That resembles depth-first exploration, even though the machinery underneath is nothing like this cave.

So "DFS is everywhere" is slightly too strong. What is everywhere is the pattern: commit to one possibility, follow it as far as it goes, and backtrack in an orderly way when it fails.
