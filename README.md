# Cave Diver — Depth-First Search

**Live: https://akshath-pg.github.io/cave-diver-dfs/**

An interactive explanation of **depth-first search**, built for Foundations of AI
(Module 1 — Searching).

A diver enters a flooded cave with one rope. He swims down one passage until it
ends, follows the rope back, and tries the next one. That is DFS. The rope *is*
the stack, drawn directly from it, so the data structure is something you watch
rather than something you are told about.

## The four modes

| Mode | What you do |
|---|---|
| **Dive** | You are the diver. The cave is dark, and the game refuses moves DFS would not make — and tells you why. Four levels. |
| **Playground** | Change the cave and watch DFS react: branching factor, depth, loops, neighbour order, treasure position, rope limit, markers, endless passage. |
| **Race** | DFS against breadth-first search or iterative deepening on an identical cave, with the memory cost of each shown side by side. |
| **Learn** | The algorithm, a worked trace, the complexity figures, and where the pattern shows up. |

## What each control is for

Every playground setting exists to make one claim testable rather than asserted:

- **Markers off** — the search never terminates. The visited set is part of the
  algorithm, not an optimisation.
- **Endless passage** — the diver commits and never returns. DFS is not complete.
- **Shallow treasure on the last branch** — DFS finds *a* solution, not the
  shallowest. DFS is not optimal.
- **Rope limit** — the search terminates, but can now miss a deeper solution.
- **Large b and m** — past 1400 chambers the cave is not drawn. The page prints
  the chamber count against the rope length instead, which is O(b^m) versus O(m)
  stated honestly.

## Running it

No build step and no dependencies. Serve the `site/` folder:

```bash
cd site && python -m http.server 8000
```

Then open `http://localhost:8000`.

## Layout

```
site/
  index.html        four views in one page
  css/styles.css
  js/graph.js       cave model, generation, tree layout
  js/search.js      DFS, BFS, iterative deepening
  js/cave.js        SVG renderer (rope, markers, fog of war)
  js/dive.js        player mode and its levels
  js/race.js        side-by-side comparison
  js/app.js         playground, learn page, mode switching
tools/
  shoot.js          screenshot capture used for the project report
docs/screenshots/   one set per version
```

Searches are recorded as a list of steps and then replayed, rather than run
live. Stepping backwards costs nothing, and the drawing code stays completely
separate from the algorithms.

## Correctness

The DFS implementation reproduces the worked trace from the course notes exactly
— all twelve steps, with the same stack and visited set at each one. The trace
table on the Learn page is generated by the same code the game runs, so the
explanation cannot drift away from the implementation.
